# Шаг 1. Требования к проекту и правила для агента

## Проект

**Планёр** — веб-приложение для списка учебных задач. Студент ведёт задания по предметам: название, описание, срок, приоритет и статус (к выполнению, в работе, готово).

Это учебный проект к курсу. В нём нет аккаунтов, оценок и персональных данных других людей. Данные задач хранятся в локальной PostgreSQL.

## Технологический стек

| Слой | Выбор |
| --- | --- |
| Интерфейс | React 19, TypeScript, Vite, Tailwind CSS 4, React Router 7 |
| Тесты интерфейса | Vitest, Testing Library |
| API | ASP.NET Core 10, контроллеры |
| Доступ к данным | Entity Framework Core, Npgsql |
| База | PostgreSQL 18, база `study_planner` |

Архитектура намеренно простая: одна страница со списком, отдельный маршрут карточки задачи, один контроллер `TasksController`. Фильтры списка считаются на клиенте, потому что у одного студента задач немного. Тот же отбор продублирован query-параметрами API, чтобы его можно было перенести на сервер без смены контракта.

## Требования к стилю и архитектуре

- Интерфейс и тексты ошибок — на русском.
- Компоненты функциональные, без классов.
- В TypeScript нет типа `any`.
- Сеть изолирована в `frontend/src/api/client.ts`. Правила предметной области (фильтр, валидация, просрочка) — чистые функции в `frontend/src/lib`.
- Стили только через Tailwind, визуально в концепции «Тетрадь»: бумажный фон, крупный заголовок, цветная полоса приоритета.
- API не отдаёт стек исключения. Ошибка базы превращается в короткое сообщение со статусом 503.
- Секреты не коммитятся. Пароль PostgreSQL в примере — заглушка `CHANGE_ME`.
- Устаревшие библиотеки (`moment`, jQuery, Bootstrap, классовые компоненты, React Router 5) не используются.

Эти требования перенесены в `.cursorrules` (16 правил, разделы Role, Context, Style, Constraints, Format). Копия для сдачи — в `docs/dz2/rules.md`.
