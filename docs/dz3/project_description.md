# Планёр. Описание продукта

## Идея

Студент хранит учебные задачи в разных местах: в чате, в заметках телефона и в голове. Срок всплывает в день сдачи. Планёр собирает задачи по предметам в один список со сроком, приоритетом и статусом.

Это не замена электронному журналу и не трекер для команды. Один человек ведёт свои задания на семестр.

## Проблема

Учебные задачи короткие, их много, и они протухают в разные дни. Общий список дел плохо показывает, какая лабораторная относится к базам данных, а какая уже сделана. Таблица в редакторе не подсказывает просрочку и неудобна с телефона по дороге в университет.

## Для кого

Основная роль — **студент** очной программы, который сам ставит себе задачи по курсам. Второго аккаунта в MVP нет: преподаватель сюда не заходит, староста не назначает задачи группе.

Ситуации, на которые рассчитан интерфейс:

- вечером записать новую лабораторную;
- утром за минуту понять, что горит;
- с телефона отметить задачу сделанной.

## Ценность

Список отвечает на три вопроса без настройки проекта и колонок: что сдавать, по какому предмету и успеваю ли я. Просроченное видно сразу. Выполненное не выглядит как провал только из-за прошедшей даты.

## Функции MVP

1. **Список задач и сводка.** Название, предмет, приоритет, статус, срок. Отдельно посчитаны все задачи, задачи в работе, ожидающие и просроченные.
2. **Создание и редактирование.** Форма: название, предмет, срок, приоритет, статус, описание. Предмет можно выбрать из уже встречавшихся или ввести свой.
3. **Статус, фильтры и поиск.** Задачу можно двигать по цепочке «к выполнению → в работе → готово» и вернуть обратно. Список сужается по статусу, приоритету, предмету и строке поиска.

За пределами MVP: регистрация, общие списки группы, вложения, уведомления, календарная сетка.

## Как этим пользоваться

Счастливый путь. Студент открывает главную, нажимает «Новая задача», заполняет форму и сохраняет. Карточка появляется в списке. В день работы он переводит её в статус «В работе», после сдачи — в «Готово». Если задач стало много, оставляет фильтр «Базы данных» и поиск по слову «SQL».

Подробная карта историй и критерии приёмки — в `user_stories.md`. Техническое задание для разработки — в `technical_specification.md`.
