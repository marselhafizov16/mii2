# User Story Mapping

## Роль

**Студент** — единственная персона MVP. Сам создаёт задачи, сам их закрывает. Отдельной роли преподавателя нет.

## Сценарии

Счастливый путь:

1. Студент открывает главную и видит сводку и список.
2. Добавляет задачу с предметом, сроком и приоритетом.
3. В день работы переводит её в статус «В работе», после сдачи — в «Готово».
4. Перед парой оставляет фильтр по предмету или ищет по слову из названия.

Обычные ответвления: правит описание, удаляет задачу, которую поставил по ошибке, открывает карточку, чтобы прочитать условие целиком. С телефона те же шаги идут в одну колонку.

Негативные ветки разобраны в критериях приёмки и в разделе «Обработка ошибок» технического задания.

## Must have

### US-1. Видеть список задач

Как студент, я хочу видеть свои учебные задачи списком, чтобы понимать, что ещё не сдано.

Критерии приёмки:

- Given в базе есть задачи, When я открываю главную, Then вижу название, предмет, приоритет, статус и срок каждой.
- Given задача не выполнена и срок раньше сегодняшнего дня, When список отрисован, Then на карточке есть метка «Просрочено».
- Given задача уже в статусе «Готово», When её срок в прошлом, Then метки «Просрочено» нет.
- Given задач нет и сервер ответил успешно, When я открываю главную, Then вижу текст «Пока пусто», а не бесконечную загрузку.

### US-2. Добавлять задачу

Как студент, я хочу создать задачу с предметом и сроком, чтобы не держать её в заметках.

Критерии приёмки:

- Given я нажал «Новая задача», When форма открыта, Then есть поля названия, предмета, срока, приоритета, статуса и описания.
- Given название короче 3 символов или пустой срок, When я нажимаю «Сохранить», Then форма остаётся открытой и показывает текст ошибки у поля.
- Given поля заполнены верно и API доступен, When я сохраняю, Then задача появляется в списке без перезагрузки страницы.
- Given API вернул ошибку валидации, When ответ разобран, Then сообщение сервера видно в форме.

### US-3. Менять статус

Как студент, я хочу двигать задачу по статусам, чтобы отделять сделанное от текущего.

Критерии приёмки:

- Given статус «К выполнению», When я нажимаю «В работу», Then статус становится «В работе».
- Given статус «В работе», When я нажимаю «Готово», Then статус становится «Готово» и задача уходит ниже невыполненных.
- Given статус «Готово», When я нажимаю «Вернуть», Then статус снова «К выполнению».
- Given запрос смены статуса завершился ошибкой сети, When ответ получен, Then прежний статус остаётся и показывается сообщение об ошибке.

### US-4. Фильтровать и искать

Как студент, я хочу сузить список, чтобы перед парой видеть задачи одного предмета.

Критерии приёмки:

- Given в списке задачи разных статусов, When выбран статус «К выполнению», Then карточки других статусов скрыты.
- Given я ввожу подстроку в поиск, When она есть в названии, предмете или описании без учёта регистра, Then задача остаётся в списке.
- Given фильтр не находит ничего, When список перерисован, Then виден текст «Ничего не нашлось».
- Given фильтр активен, When я смотрю сводку, Then числа считаются по всем задачам, а не только по отфильтрованным.

### US-5. Видеть просроченное в сводке

Как студент, я хочу видеть число просроченных задач, чтобы не открывать каждую карточку.

Критерии приёмки:

- Given есть невыполненная задача со сроком до сегодня, When сводка построена, Then счётчик «Просрочено» учитывает её.
- Given эта задача переведена в «Готово», When сводка пересчитана, Then она больше не входит в «Просрочено».
- Given срок равен сегодняшнему дню, When задача не выполнена, Then она не считается просроченной.

## Should have

### US-6. Редактировать задачу

Как студент, я хочу исправить срок или предмет, чтобы список не врал после переноса дедлайна.

Критерии приёмки:

- Given я нажал «Изменить», When форма открыта, Then поля заполнены текущими значениями.
- Given я сохранил новый срок, When запрос успешен, Then карточка показывает новый срок.
- Given задачи с таким id нет, When сервер ответил 404, Then я вижу «Задача не найдена».

### US-7. Удалять задачу

Как студент, я хочу удалить лишнюю задачу, чтобы она не висела в списке.

Критерии приёмки:

- Given я нажал «Удалить», When подтверждение ещё не дано, Then задача не удалена и видны действия «Да» и «Нет».
- Given я подтвердил удаление и API ответил 204, When список обновлён, Then карточки больше нет.
- Given удаление не удалось, When пришла ошибка, Then карточка остаётся и ошибка показана на странице.

### US-8. Открывать задачу целиком

Как студент, я хочу открыть задачу отдельно, чтобы прочитать длинное описание.

Критерии приёмки:

- Given я перешёл по названию, When страница загрузилась, Then видны описание, статус, приоритет и срок.
- Given id неизвестен серверу, When пришёл 404, Then показано «Задача не найдена» и ссылка «К списку».
- Given ширины экрана мало, When страница открыта, Then текст не вылезает за край, действия стоят столбцом.

## Nice to have

### US-9. Подсказка предмета

Как студент, я хочу выбирать предмет из уже использованных, чтобы не плодить «БД» и «Базы данных».

Критерии приёмки:

- Given в списке уже есть предмет, When открыта форма, Then его можно выбрать из подсказок.
- Given я ввожу новое название предмета, When сохраняю, Then оно принимается и потом появляется в фильтре.

В этой версии подсказка сделана через `datalist`, без отдельного справочника в базе.

## Приоритеты одной строкой

| История | Приоритет |
| --- | --- |
| US-1 Список | Must |
| US-2 Создание | Must |
| US-3 Статус | Must |
| US-4 Фильтры и поиск | Must |
| US-5 Сводка просрочки | Must |
| US-6 Редактирование | Should |
| US-7 Удаление | Should |
| US-8 Карточка задачи | Should |
| US-9 Подсказка предмета | Nice |

Must закрывают обещание MVP из `project_description.md`. Should нужны, чтобы списком можно было пользоваться дольше одного вечера. Nice не блокирует сдачу.
