# ДЗ 4. Отчёт о разработке фронтенда

Проект: **Планёр**. Клиент: React, TypeScript, Vite, Tailwind CSS. Макет — концепция «Тетрадь» из ДЗ 3. Правила агента — `.cursorrules` из ДЗ 2. Промпты по форме RTCF — из `docs/dz2/prompt_templates.md`.

Агент: Cursor. Он же выбран в ДЗ 1.

## Шаг 1. Техническое задание

Взято ТЗ из ДЗ 3 (`docs/dz3/technical_specification.md`), не писалось заново.

Три функции, которые обязаны работать:

1. список задач со сводкой и просрочкой;
2. создание и редактирование;
3. статус, фильтры и поиск.

Стек клиента зафиксирован в ТЗ: React 19, Vite, Tailwind 4, React Router 7. Библиотека компонентов не подключалась: для бумажного макета хватает утилит Tailwind, второй UI-кит спорил бы с концепцией.

## Шаг 2. Инициализация

Промпт:


Окружение на машине: Node.js 24, .NET SDK 10, PostgreSQL 18 как служба Windows. Docker не понадобился.

## Шаг 3. Базовая структура

Промпт на раскладку каталогов — шаблон декомпозиции из ДЗ 2, затем отдельные просьбы на файлы:

- `src/types.ts` — задача, черновик, фильтр;
- `src/api/client.ts` — единственное место с `fetch`;
- `src/lib/` — даты, подписи, фильтр и валидация;
- `src/components/` — карточка, форма, фильтры, сводка, каркас;
- `src/pages/BoardPage.tsx` и `TaskDetailsPage.tsx`;
- маршруты `/` и `/tasks/:id` в `App.tsx`.

API: `GET/POST /api/tasks`, `GET/PUT/DELETE /api/tasks/{id}`, `PATCH /api/tasks/{id}/status`.

## Шаг 4. Компоненты

Промпт карточки приведён в ДЗ 1 и в шаблоне «генерация компонента». Карточка не ходит в сеть: статус, правка и удаление приходят колбэками. Просрочка считается функцией `isOverdue`, выполненная задача с прошедшим сроком метку не получает.

Форма закрывает три состояния сама:

- ошибка поля до запроса (короткое название, пустой предмет, пустой срок);
- `saving` на кнопке «Сохраняем…»;
- текст ошибки API, если сервер ответил 400 или 503.

Список: «Загружаем задачи…», пустая база («Пока пусто»), пустой фильтр («Ничего не нашлось»), ошибка сети с кнопкой «Повторить». Если список не загрузился, нулевая сводка не показывается: иначе кажется, что задач правда ноль.

Стили — концепция «Тетрадь»: фон `#efe7da`, карточка `#fffaf3`, акцент `#d85a2a`, заголовок Fraunces, текст Manrope.

## Шаг 5. Тесты и отладка

Команда `npm test`. Семь тестов в трёх файлах:

- фильтр оставляет задачу со статусом «к выполнению» и словом «sql» в названии;
- сводка считает просрочку и не включает выполненное;
- валидация: короткое название, пустой срок, корректный черновик;
- карточка показывает «Просрочено» и не показывает её у уже сделанной задачи.

Падение, которое поймал прогон:

```text
FAIL TaskCard > не помечает просроченной уже выполненную задачу
expected document not to contain element, found <span>Просрочено</span>
```

Промпт на починку — шаблон «исправление ошибки». Первая гипотеза была неверной: функция `isOverdue` для `status === "done"` и так возвращает `false`. В выводе теста спан остался от предыдущего рендера. У Vitest без глобального `afterEach` Testing Library не убирает DOM. В `src/test/setup.ts` добавлен `cleanup()`. После этого все 7 тестов проходят.

Отдельно в браузере проверена пустая форма: «Сохранить» без полей показывает три текста ошибок и не закрывает окно. Это клиентская валидация, сеть для неё не нужна.

Пока в `appsettings.json` пароль `CHANGE_ME`, API живой (`/api/health` отвечает `ok`), а `GET /api/tasks` отвечает 503 с коротким текстом. Клиент показывает этот текст и «Повторить», без заглушки «Пока пусто». Стек исключения в браузер не попадает, он остаётся в консоли сервера.

## Шаг 6. Адаптив

Промпт:

```text
Role: Frontend-разработчик. Следуй .cursorrules.
Task: Проверь вёрстку на ширине 390 и 1440. Фильтры на узком экране должны встать над списком, форма — снизу на всю ширину. Горизонтального скролла страницы быть не должно.
Context: Концепция «Тетрадь». Брейкпоинт колонки — lg.
Format: Правки только в классах Tailwind. Напиши, что измерял.
```

На 1440 фильтры слева, список справа. На 390 одна колонка: кнопка «Новая задача», чипы статуса в ряд, сводка была бы 2×2, форма открывается нижним листом, кнопка «Сохранить» на всю ширину, «Отмена» под ней.

Проверка в браузере: `documentElement.scrollWidth === clientWidth === 390`, лишней ширины нет.

Что всплыло на скриншоте 390 px: подзаголовок и сообщение про базу хотели вылезти за край из-за длинного слова `ConnectionStrings:DefaultConnection` и flex-элемента без `min-w-0`. Текст ошибки на сервере сокращён до человеческой фразы, у абзаца ошибки стоит `break-words`, у шапки `min-w-0`. Повторный снимок — `docs/dz4/screenshots/mobile.png`.

Широкий экран — `docs/dz4/screenshots/desktop.png`.

## Шаг 7. Рефакторинг

Отдельный промпт на дату (шаблон рефакторинга): не использовать `new Date("YYYY-MM-DD")`, потому что такая строка читается как UTC и в UTC+3 съезжает на предыдущий день. Итог — `parseIsoDate` в `src/lib/dates.ts`. Сравнение черновика без правил и этого варианта — в `docs/dz2/testing.md`.

Фильтры вынесены из компонента в чистые функции, чтобы их тестировать без браузера. Это описано цепочкой промптов в `docs/dz2/prompt_methodology.md`.

По ходу просмотра экрана убрана ещё одна путаница: при ошибке первой загрузки одновременно могли быть и баннер, и «Пока пусто». Пустое состояние рисуется только после успешного ответа.

## Шаг 8. Что оказалось полезным

- Правила в `.cursorrules` до кода. Без них первая функция даты приехала с `any` и сдвигом суток.
- Короткий промпт на один файл лучше, чем «сделай всё приложение» одним сообщением. Цепочка из ДЗ 2 это подтвердила на фильтрах.
- Упавший тест полезнее пересказа. Формулировка из вывода Vitest сразу отделила баг очистки DOM от бага просрочки.
- Скриншот узкой ширины поймал то, что тест на jsdom не видит: длинное слово в баннере ошибки.

Ограничение этого прогона: список с сидами не открывался, потому что пароль локального PostgreSQL в репозиторий не записывался. После замены `CHANGE_ME` API создаёт базу `study_planner` и шесть учебных задач. До этого интерфейс честно показывает, что базы нет.
